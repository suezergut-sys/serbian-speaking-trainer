# Проверка попыток при параллельных запросах — 30.09.2026

Эта контрольная точка описывает реализацию P1.2 и часть P1.4. Независимое ревью, локальные проверки и публикация web/backend завершены. Нагрузка через production pooler, авторизованный production-сценарий, полный P1 и ручная приёмка остаются открытыми.

## Изменения

- Проверка ответа разделена на короткое резервирование, вызов AI вне транзакции и атомарное сохранение результата. Резерв удерживает блокировку пользователя только на коротком участке работы с БД.
- Попытки резервируются с истечением lease и монотонным fencing token. Идентификатор клиентского запроса сохраняется для повторов; истёкшая резервация может быть захвачена с новым token, а устаревший обработчик не должен финализировать её результат.
- Резерв учитывает дневные слоты и уникальные упражнения сессии. Ошибка AI освобождает слот; просроченные резервы можно заменить. Превышение реальной дневной квоты остаётся `429`; конфликт с активной резервацией возвращает retryable `409 attempt_in_progress` и `Retry-After: 1`.
- Длительность lease рассчитывается из настроек AI: `max(60, 2 × timeout × (max_retries + 1) + 30)` секунд, чтобы покрыть два прохода анализатора и запас на завершение.
- Клиент немедленно показывает подсказку, дедуплицирует повторную отправку слова, блокирует правку ответа и подсказки во время проверки и повторяет ту же попытку с тем же ID и текстом. Серверный маркер упражнения/слова не позволяет повторно учитывать одну и ту же подсказку; финализация сохраняет валидированный список подсказанных слов, в том числе если фоновая запись не завершилась до финализации.
- Миграция `e926b83f4d10` добавляет три nullable reservation-поля (`exercise_id`, `reserved_at`, `lease_expires_at`) и `fencing_token NOT NULL DEFAULT 1`, сохраняя совместимость исторических строк.

## Проверки и измерения

- Frontend: 59 тестов, TypeScript, lint и production build прошли; production build сообщает о существующем large-chunk warning.
- Парный локальный benchmark (`scripts/testing/benchmark_attempt_lock.py`): Windows, свежая файловая SQLite на каждый запуск, два потока и fake AI с паузой 1000 мс; по 3 прогрева и 20 измерений на одинаковой фикстуре. До: writer p50 1105,23 мс, p95 1118,25 мс; открытая транзакция во время AI в 20/20 запросов, competing writer завершился во время AI в 0/20. После: writer p50 8,40 мс, p95 9,62 мс; транзакция открыта во время AI в 0/20, writer завершился во время AI в 20/20. Хеш одинаковой фикстуры `21cc325bcf577c934cb6f9daa2414f90ffd49df8c3eaa0bcc4b5249d0844bef8`; отчёты: `artifacts/testlab/attempt-lock/before-20260930T152600182576Z/report.json` и `artifacts/testlab/attempt-lock/after-20260930T154738058186Z/report.json`. Это измеряет ожидание независимой SQLite-записи, не полную скорость API-проверки с AI.
- Backend: полный набор после UTC-коррекции — 120 passed, 7 skipped без PostgreSQL DSN. Все 24 проверки вспомогательных scripts прошли. Отдельный набор резервирования/идемпотентности/миграции на локальном PostgreSQL 17.11 — 15 passed без пропусков, включая 7 ранее пропущенных случаев; каждый DB-тест создавал изолированную схему. Это не нагрузочный тест Supabase production pooler.
- Миграция проверена для старой, актуальной и чистой базы; существующая история сохраняется, неизвестная revision не принимается. Проверки вспомогательных scripts: 12 unit-тестов; testlab: 11 pytest-проверок.
- Независимое ревью GPT-6.1 Sol / medium завершено: Accepted, замечаний не осталось. Проверено резервирование на переходе UTC-суток после исправления фиксации времени под обеими блокировками; дополнительные регрессионные случаи прошли в SQLite и PostgreSQL.
- Web E2E с локальным backend: 2 проверки прошли. Сценарий с реальным endpoint подсказки подтвердил немедленное отображение, единственный штраф 92% при двойном нажатии, переход к следующей фразе до завершения POST и безопасное игнорирование позднего HTTP 503.
- Полный Android lab проход на установленном APK 1.15 прошёл (`scripts/run-testlab.ps1 -Platform android`). APK использует прежний client bundle, поэтому это подтверждает backend-совместимость и общий сценарий; новая клиентская логика подсказок ожидает контрольного выпуска.
