# Язык исходной фразы — 30.10.2026

## Диагноз

В production проверены 210 общих фраз: исходники и сербские каноны полностью совпадают с seed, у всех есть EN-перевод, кириллицы в EN нет. Проверены агрегаты личного каталога: 9 фраз, все с русским исходником, отдельных переводов не было. Тексты личных фраз, аудио, секреты и полные диагностические payloads в этот документ/Git не включаются.

Для аккаунта владельца просмотрены текстовые метаданные упражнений за 30.10 (с 00:00 МСК) и только текстовый input диагностики, без бинарного аудио. В 14:39–14:42 выдавались общие и личные упражнения. В двух вызовах answer_analyzer_v4 (14:40:39/43 МСК) явно указан feedback_language=en, общий исходник передан на английском. Заголовки/язык отображения каждого упражнения не логировались, поэтому по одному source_ru в SQL нельзя утверждать, что общий исходник показывался на русском: это историческое поле оригинала.

Причина подтверждена кодом: renderPhrase переводил текст через локальный словарь общих фраз и использовал source_en только как флаг. Персональные фразы с source_en=null оставались на исходном языке; переключение интерфейса переводило общие фразы, сохраняя русские личные. Backend не имел двух языковых версий личного текста. Исходник пользователя, transcript и evidence не нормализуются под перевод.

## Исправление

- SourceVersions: независимые ru/en тексты и hints_ru/hints_en. Pydantic проверяет structured AI output, русский текст в RU и отсутствие кириллицы/наличие латинского текста в EN. Это проверка структуры/письменности; смысл дополнительно обеспечивается prompt и приёмкой перевода, не обещается универсальное определение языка по алфавиту.
- Новая подготовка phrase_preparation_v4 создаёт обе версии за один AI-вызов, сохраняя оригинал дословно и прежний канон при его передаче. Общая policy Ekavica проверяет также оба словаря подсказок. Timeout/retry и model IDs — существующие backend env settings.
- Миграция f0e065fafe11 добавляет review_phrases.source_versions_json. Прогресс, оригиналы, сербские варианты и история не переписываются. Downgrade удаляет только восстанавливаемый кэш переводов; upgrade повторяем через Alembic.
- Кэш привязан к точной паре оригинал/канон, доступ owner-scoped. Старые snapshots не получают перевод для другого канона. Обычная тренировка, конкретное повторение, карусель и idempotent response получают source_text/source_language и обе версии. Отсутствующий запрошенный язык даёт безопасный retryable503 вместо подмены.
- Web выбирает текст и подсказки по текущему языку из одного ответа, включая поздний/prefetched ответ и мгновенное переключение RU/EN. Повторная сеть при переключении не нужна. Нет молчаливого fallback на чужой язык; некорректная версия блокирует задание и предлагает перезагрузку.
- Подготовка личной фразы показывает обе версии перед сохранением RU/EN, каталог Premium выбирает текущую версию. Проверка ответа получает соответствующий исходник; подсказки обоих языков привязаны к одному immutable канону.
- Legacy source_ru в API/БД остаётся исходным текстом. История и transcript/evidence не переписываются. Персональные оригиналы в статистике являются историческими данными, не заданиями для нового перевода.

## Operator backfill

Из backend: `python scripts/backfill_source_versions.py --env-file ../artifacts/source-language-operator.env` — dry run. С `--execute` выполняется явное разрешённое владельцем дополнение существующих личных фраз переводами; повтор пропускает валидные кэши. Оператор должен предоставить реальные непустые backend DATABASE_URL и AI env; sensitive values из Vercel env pull могут быть пустыми. Скрипт отказывает до импорта DB/AI, не подменяет production локальной SQLite. Из env-файла импортируются только необходимые настройки перевода. Значения не печатаются. Можно ограничить `--owner-email`. Ошибка валидации останавливает обработку; ранее завершённые записи сохранены. Переводы проверяются по original/canonical и независимым hints. AI budget используется только для порученного реального перевода, не в автоматических tests.
