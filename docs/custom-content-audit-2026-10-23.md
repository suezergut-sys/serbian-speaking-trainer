# Пользовательские темы и фразы — 23.10.2026

> Обновлено по следующей команде владельца: доверие к клиентскому canonical, лимиты и удаление переработаны. Актуальное поведение и проверки — [личный каталог, лимиты и удаление](custom-content-limits-2026-10-23.md). Ниже сохранён исходный аудит.

## Результат и статус

Локально включены кнопки «+ добавить тему» и «+ добавить фразу» для `account.role === "admin"`. Для обычных аккаунтов, включая premium без роли admin, кнопки остаются disabled с Premium badge. Включение выполнено в desktop и общем web/mobile/Android-layout; APK 1.38/code48 не синхронизировался и не пересобирался. Публикация не выполнялась.

## Как работает

1. **Тема:** ввод названия (2–160 символов), «Сохранить тему». Backend схлопывает пробелы и создаёт пустую личную тему; автоматической генерации фраз нет. Название без учёта регистра и нормализация пробелов дают тот же ID в рамках аккаунта, поэтому повторное сохранение возвращает существующую тему.
2. **Фраза:** ввод текста **на русском языке** (3–240 символов), «Подготовить перевод». `POST /api/review-phrases/prepare` вызывает AI-адаптер с версионируемым prompt `phrase_preparation_v2.md`; Pydantic проверяет варианты и подсказки. Ответ ещё не создаёт карточку в БД.
3. Отображается первый сербский вариант с учётом выбранного алфавита; пользователь выбирает тему и нажимает «Сохранить фразу». `POST /api/review-phrases` сохраняет исходный текст, canonical/варианты, подсказки и `topic_id`. При изменении исходного текста preview сбрасывается. При ошибке подготовки/сохранения сохраняются черновик и доступные результаты для повтора; на время запроса отправка и закрытие заблокированы.
4. Сохранённая карточка появляется в повторении и доступна в выбранной теме. После сохранения клиент обновляет список тем и summary повторения. Создание темы отражается в каталоге сразу без перезагрузки.
5. Данные личные, включая добавленное администратором: общим каталогом они не становятся. В интеграционном тесте второй аккаунт не видит личную тему/фразы и получает 404 при попытке добавить в чужую тему или запустить её.
6. Добавленная фраза использует существующий цикл повторения: три самостоятельных результата >=95% подряд; текущая трудность и интервалы рассчитываются ReviewService. Добавление само по себе не считается проверенной попыткой.
7. RU/EN относятся к интерфейсу. Произвольные пользовательские тексты не переводятся автоматически для английского интерфейса: ввод фразы остаётся на русском, название личной темы сохраняется как введено.

## Найденное и исправленное

- Кнопки были безусловно disabled, обработчиков и доступных форм не было; существующие API-функции клиента не использовались. Теперь формы открываются только администратору, без Premium badge.
- Названия и исходные фразы из пробелов проходили исходные Pydantic length checks, после нормализации становились пустыми. Request-схемы теперь обрезают внешние пробелы до проверки длины; пустой canonical также отклоняется 422.
- Невалидный structured output при подготовке мог пробросить Pydantic ValidationError. Теперь это безопасный 503; пустые и слишком длинные (>300) варианты также отклоняются. Варианты нормализуются по пробелам.
- Для форм добавлены явные тёмные цвета input/select/button/disabled/error и RU/EN состояния подготовки, сохранения, ошибки и успеха.

Нужен серверный receipt/повторная валидация, если требуется гарантированно проверенный эталон. |
| P1 | Дубликат определяется по нормализованному исходному тексту для всего аккаунта, без темы. Поведение воспроизведено интеграционным тестом; в форме теперь есть предупреждение. Нужно определить ожидаемую политику дублей и сохранения прогресса. |

SDK timeout и bounded retry уже настроены через env; UI ждёт до 30 секунд. |
| P2 | Нет интерфейса удаления/переименования темы, удаления карточки и ручной правки preview-перевода. Закрытие/смена формы теряет несохранённый черновик. | Исправлять пользовательский каталог неудобно; для неверного preview нужно изменить текст и повторить подготовку. |
