# P1.4 — восстановление после сетевых ошибок, 01.10.2026

Этот срез проверяет, что сбой запроса оставляет пользователю путь продолжения без перезагрузки и потери текущего ответа. Основной план: [audit-roadmap.md](audit-roadmap.md). Полный P1, перенос в Android и ручная приёмка отмечаются отдельно.

## Подтверждённые проблемы

- После неудачного первоначального GET тем нет доступного действия повторить загрузку.
- После ошибки первой расшифровки ручное поле ответа скрыто.
- Начало повторной записи очищает уже введённый ответ до получения нового transcript; отказ микрофона или ошибка STT теряет этот текст.
- Ответ STT может заменить текст, вручную исправленный во время ожидания расшифровки.
- Неудачный prefetch следующей фразы оставляет отклонённый Promise в кеше: первое нажатие «Следующая» повторяет старую ошибку, и только второе создаёт новый запрос. Исправление удаляет неудачный Promise и сохраняет request ID; первое нажатие повторяет запрос.

## Метод проверки

Автоматические сценарии используют отдельную mock-сборку либо изолированный testlab с настоящим локальным backend и mock AI/STT. Recorder генерирует синтетические байты только в памяти. Пользовательское аудио, credentials, HAR, trace, видео и snapshots не сохраняются.

Для проверки потерянного ответа серверу дают сохранить попытку, после чего браузер получает сетевой отказ. Повтор должен использовать тот же client request ID, вернуть тот же attempt и не увеличить completed_count или дневное использование второй раз. Дополнительно проверяются отказ запроса до отправки, восстановление соединения и поздние ответы предыдущего упражнения.

Runner локального web: `scripts/run-testlab.ps1 -Platform web -Suite network`; обычная практика — `-Suite practice`, обе группы — `-Suite all`. На Android runner проверяет установленный lab-клиент; это не перенос новой реализации в APK. Методика окружения: [testlab.md](testlab.md).
