# Продажа Premium SerboTalk через Google Play: инструкция владельцу

Актуальность официальных источников проверена **26.10.2026**. Это инструкция для будущей настройки, а не отчёт о выполненных действиях в аккаунте. Play Console и Google Cloud в этой задаче не изменялись. Названия пунктов могут отличаться по языку и варианту интерфейса; ниже приведены английские ориентиры.

## 1. Что настраиваем и в каком порядке

Согласовано владельцем: **Premium за 5 EUR однократно и бессрочно**, без ежемесячного списания. Android использует Google Play Billing; web сохраняет отдельный платёжный сценарий. Общим остаётся право Premium у аккаунта SerboTalk. Полный контракт: [разделение каналов](premium-payment-channels.md).

Для Google это one-time product, используемый нашим приложением как **non-consumable**. Бессрочность реализуется в учёте прав SerboTalk; нельзя вызывать consume после покупки. Выбор non-consumable не обязательно представлен отдельным переключателем Console. [Типы разовых продуктов Google](https://developer.android.com/google/play/billing/one-time-products).

Порядок: профиль продавца и выплаты → товар → серверный API → тестировщики → Billing-сборка в тестовом треке → уведомления и возвраты → приёмка → production.

В аккаунте уже есть SerboTalk; создавать второе приложение или новый аккаунт разработчика для Premium не требуется. Package name в исходниках: `com.serbiantalk.trainer`. Перед настройкой сравнить его с приложением в Console. Числовой Console app ID, package name и product ID — разные идентификаторы. Историческая подготовка карточки описана в [Google Play setup](google-play-setup-2026-10-12.md); её старые статусы не заменяют проверку текущего Dashboard.

**Можно подготовить сейчас:** пункты 2–6 и проект/тему уведомлений. **Зависит от реализации:** загрузка Billing-сборки, рабочий URL уведомлений, проверка API и реальные тестовые покупки. Создание товара само по себе не добавляет оплату в APK 1.40.

## 2. Проверить аккаунт разработчика и страну продавца

Войти владельцем в [Google Play Console](https://play.google.com/console/). Проверить Account details/Developer account и Dashboard: нет ли незавершённой проверки личности/организации, контактов или обязательных соглашений. Оплата регистрации разработчика и наличие профиля для проверки личности сами по себе ещё не означают, что настроен merchant account для продаж. [Требования к аккаунту и выплатам](https://support.google.com/googleplay/android-developer/answer/13628312?hl=en).

До ввода реквизитов определить реальную страну продавца и банка. Если это Сербия, Google указывает поддержку merchant registration и валюту профиля по умолчанию USD; из этого не следует, что цена покупателю или валюта банковского счёта обязательно EUR. Для другой страны проверить её строку. [Поддерживаемые страны](https://support.google.com/googleplay/android-developer/answer/9306917?hl=en).

Если счёт для выплат находится в России, по действующему уведомлению Google продажи через Play для такого продавца приостановлены, включая покупки пользователей других стран. Указанная в общей таблице возможность регистрации не отменяет этого ограничения. Сначала решить вопрос допустимого платёжного профиля и выплат с Google; настройка товара не устраняет блокировку. [Приостановка seller services](https://support.google.com/googleplay/android-developer/answer/15685001?hl=en).

Результат этапа: известны владелец аккаунта, реальная страна профиля, страна банка и доступность монетизации. Банковские номера и документы в репозиторий не записывать.

## 3. Создать профиль продавца

Это настройка **аккаунта**, а не конкретного товара.

1. Открыть Payments profile. В разных версиях интерфейса путь выглядит как **Settings → Monetization → Payments profile** либо **Manage account → Play apps settings → Monetization settings → Payments profile**.
2. Если merchant profile уже существует, проверить его, а не создавать дубликат. Иначе выбрать **Create payments profile**.
3. Указать реальные юридические данные и адрес, соответствующие документам, страну, контакт владельца/представителя.
4. Заполнить публичные данные продавца: сайт `https://serbotalk.app`, действующий email поддержки и понятное название в банковской выписке, например `SerboTalk`.
5. Отправить данные и завершить проверки, которые запрашивает Google. Страну профиля нельзя просто отредактировать после создания; не выбирать её только ради нужной валюты.

Источник: [создание payments profile](https://support.google.com/googleplay/android-developer/answer/7161426?hl=en).

**Проверка:** профиль привязан к аккаунту и в нём нет незавершённых обязательных действий. Профиль продавца Google не заменяет настройки web-оплаты СБП/ALTA/PayPal.

## 4. Настроить получение денег и обязательные сведения

1. В Payments profile открыть **How you get paid → Add payment method**. Управление merchant payment accounts доступно владельцу аккаунта.
2. Внести банковские данные точно по документам банка. Счёт должен принимать подходящие переводы; обычно требуется совпадение страны счёта и профиля, с отдельным исключением для SEPA в ЕЭЗ. Допустимую валюту и способ EFT/Wire сверить по стране.
3. Если Google требует подтверждение, выполнить показанную процедуру: например, проверку депозита или документов. Наличие сохранённой строки банка ещё не означает завершённую проверку.
4. Проверить запросы налоговых сведений и иные обязательные действия в Payments center. Заполнять применимые к фактическому продавцу формы; здесь нет универсального выбора «для всех стран».
5. Проверить отсутствие блокировки выплат и сохранение реквизитов в правильном профиле.

Источники: [банк для merchant payouts](https://support.google.com/googleplay/android-developer/answer/7161440?hl=en), [проверка способа выплат](https://support.google.com/googleplay/android-developer/answer/13628312?hl=en).

Комиссия Play и налоги влияют на сумму к получению: цена 5 EUR не равна чистой выплате 5 EUR. Перед запуском проверить применимую программу и актуальную комиссию для **разовых товаров**, страны и аккаунта; не использовать ставку подписок. Если Console предлагает оформление 15% service fee tier, отдельно проверить условия участия и связанные аккаунты. [Текущие service fees](https://support.google.com/googleplay/android-developer/answer/112622?hl=en).

## 5. Создать товар Premium

Открыть **SerboTalk → Monetize with Play → Products → One-time products → Create one-time product**. Если виден старый пункт In-app products, свериться с актуальной справкой. [Создание разового товара](https://support.google.com/googleplay/android-developer/answer/16430488?hl=en).

Предлагаемая карточка для SerboTalk — это **новые примеры, ещё не созданные в аккаунте**:

| Поле | Что ввести |
| --- | --- |
| Product ID | `premium_lifetime` — сначала проверить отсутствие такого товара |
| Name RU | `SerboTalk Premium — бессрочно` |
| Name EN | `SerboTalk Premium — lifetime` |
| Description RU | `Однократная покупка Premium: 100 повторений в день, до 5 личных тем и до 30 фраз в каждой теме. Без автоматического продления.` |
| Description EN | `One-time Premium purchase: 100 repetitions per day, up to 5 personal topics and up to 30 phrases per topic. No automatic renewal.` |

Product ID нельзя позднее изменить или повторно использовать. Не добавлять в него цену/версию APK, которые могут измениться. В настройках налогов/compliance указать фактические свойства услуги; не выбирать освобождение от налогов без оснований. Если Console показывает классификацию Digital content/Service, сверить её с описанием онлайн-тренажёра. [Правила идентификатора и условия доступности](https://support.google.com/googleplay/android-developer/answer/1153481?hl=en).

Для нашего первого выпуска создать один вариант:

| Параметр | Наш выбор |
| --- | --- |
| Purchase option ID | Предлагается `lifetime` |
| Purchase type | **Buy**, бессрочная покупка |
| Rent, rental period | Не используются |
| Quantities and limits / multi-quantity | Не включать покупку нескольких экземпляров |
| Offers / pre-order | На первом этапе не добавлять |

Сохранить фактические Product ID и Purchase option ID в передаваемые разработчику данные. Они должны совпадать с будущей конфигурацией backend и native adapter; приведённые примеры пока не являются настройками приложения.

## 6. Установить цены, страны и активировать вариант

В **Availability and pricing** выбрать нужные страны, задать цену через **Set prices / Bulk edit pricing**, затем проверить таблицу локальных цен. Для EUR-регионов проекта целевой ценник — **5.00 EUR**; при необходимости скорректировать конкретные строки. Другие цены согласовать после конвертации, налогов и округлений Google. В актуальной модели цена задаётся у purchase option, а не через прежнюю единую Default price.

Проверить пересечение стран приложения и товара: доступность товара не расширяет доступность самого приложения. После проверки нажать **Activate** и убедиться, что нужный вариант **Active**, а не Draft/Inactive. [Региональные цены, доступность и активация](https://support.google.com/googleplay/android-developer/answer/16430488?hl=en).

Не активировать неподготовленную продажу ради проверки формы: активный товар может стать доступным для покупки, даже если приложение ещё не опубликовано в production. На этапе разработки использовать контролируемый тестовый сценарий и не считать отсутствие публичного релиза защитой от настоящих списаний. [Условия продажи активных товаров](https://support.google.com/googleplay/android-developer/answer/1153481?hl=en).

**Результат:** один бессрочный товар, один Buy-вариант, согласованные страны/цены и зафиксированный статус. Android должен показывать цену из Google ProductDetails, а не строку web-формы.

## 7. Дать backend доступ к Google Play Developer API

Здесь участвуют **две консоли**. Google Cloud управляет сервисной учётной записью; Play Console разрешает ей работать с покупками SerboTalk. OAuth-вход пользователей SerboTalk/Supabase — отдельная настройка.

1. В [Google Cloud Console](https://console.cloud.google.com/) выбрать подходящий проект или создать выделенный, например с отображаемым именем `SerboTalk Billing`. Записать фактический Project ID.
2. В **APIs & Services → Library** найти **Google Play Android Developer API** (`androidpublisher.googleapis.com`) и включить.
3. В **IAM & Admin → Service Accounts → Create service account** создать, например, `serbotalk-play-backend`. Записать email `…@…iam.gserviceaccount.com`. Не выдавать ему Owner/Editor проекта ради Billing.
4. В **Play Console → Users and permissions → Invite new users** указать этот email, предоставить доступ к SerboTalk и необходимые Billing-права: **View financial data, orders, and cancellation survey responses**, **Manage orders and subscriptions**. Если интерфейс разделяет видимость приложения и финансовые права по вкладкам, настроить обе части, ограничив область SerboTalk, где это допускается.
5. Сохранить/пригласить и проверить выданный доступ. Серверная учётная запись не должна получать права публикации релизов только ради проверки платежей.

Современная инструкция Google прямо указывает: старое обязательное связывание developer account с Cloud Project больше не требуется. [Developer API: актуальная настройка](https://developers.google.com/android-publisher/getting_started).

### Как backend получит credentials

Сначала выбрать способ аутентификации для хостинга: поддерживаемая федерация/короткоживущие credentials предпочтительнее постоянного ключа. Если для нашей реализации необходим JSON-ключ: **Service account → Keys → Add key → Create new key → JSON**. Хранить его в секретах **backend**, вне Git и frontend. Не отправлять содержимое ключа в чат/issue и не использовать `VITE_*`. При запрете создания ключей политикой организации согласовать допустимый способ, а не отключать политику вслепую. [Ключи и альтернативы](https://docs.cloud.google.com/iam/docs/keys-create-delete).

Названия будущих env-переменных Billing ещё не реализованы. Не добавлять выдуманный набор env в production как «готовое подключение». После реализации разработчик должен подтвердить успешный авторизованный API-запрос и безопасную ошибку для чужого/невалидного token.

## 8. Настроить бесплатные тестовые покупки

1. На уровне аккаунта Console открыть **Settings → License testing**.
2. Создать/выбрать email list с одним-двумя контролируемыми Google-аккаунтами владельца/разработчика либо использовать подходящую Google Group.
3. Добавить эти аккаунты в license testers, сохранить. Если показан License response, оставить обычный нормальный ответ для тестирования покупок; это не настройка уровня Premium.

[Настройка license testers](https://support.google.com/googleplay/android-developer/answer/6062777?hl=en).

Затем в SerboTalk открыть **Test and release → Testing → Internal testing** либо согласованный существующий закрытый трек. Добавить туда нужных тестировщиков; новый Billing AAB загружает разработчик после отдельной команды на Android-релиз. Тестировщик принимает приглашение через opt-in URL и устанавливает нужную версию из Play. Существующую группу закрытого теста и её участников не заменять ради одного платежного теста.

Это **два списка с разным назначением**: трек даёт приложение, License testing — тестовые способы оплаты. Участник трека без статуса license tester может заплатить настоящие деньги. На устройстве выбрать правильный Google-аккаунт; в окне покупки проверить тестовую отметку и тестовую карту. Устройство с несколькими аккаунтами может использовать аккаунт установки. [Тестирование Billing](https://developer.android.com/google/play/billing/test).

Если бесплатная тестовая карта отсутствует, остановить покупку и проверить аккаунт/списки. Play Billing Lab можно использовать дополнительно; для первого сценария достаточно обычной тестовой покупки.

Публичный production-релиз не нужен, чтобы начинать тестирование Billing. Для новых личных developer accounts требования к доступу в production рассматриваются отдельно: Google указывает закрытый тест с 12 участниками непрерывно 14 дней и последующую заявку. Это не основание начинать существующий тест SerboTalk заново; текущую стадию проверять по Dashboard. [Условия production access](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en).

## 9. Подготовить уведомления о покупках и возвратах

Наш проект должен получать изменения на backend даже при закрытом приложении. URL обработчика пока **не реализован**; его предоставляет разработчик. Не подставлять лендинг или произвольный существующий endpoint.

В Google Cloud включить **Cloud Pub/Sub API**, создать topic, например `serbotalk-play-rtdn`. На **этом topic** выдать **Pub/Sub Publisher** учётной записи Google:

`google-play-developer-notifications@system.gserviceaccount.com`

В **SerboTalk → Monetize → Monetization setup → Real-time developer notifications** указать полное имя `projects/<PROJECT_ID>/topics/<TOPIC_ID>`, выбрать **все уведомления, включая one-time products и voided purchases**, сохранить. Кнопка **Send test message** проверяет публикацию события; отдельно убедиться в его получении backend. [Настройка RTDN](https://developer.android.com/google/play/billing/getting-ready).

Для HTTPS push-доставки разработчик/администратор создаёт subscription к topic: **Delivery type = Push**, Endpoint URL = выданный публичный HTTPS URL, **Authentication включена**, выбрана отдельная push-auth service account и согласован audience. Настраиваются `iam.serviceAccounts.actAs` для создающего подписку и право `iam.serviceAccounts.getOpenIdToken` для Pub/Sub service agent на push-auth account — при необходимости через Service Account Token Creator. Не путать этот service agent, API-account backend и Google-отправителя выше. Backend проверяет подпись Google, issuer, audience и ожидаемый email в OIDC token. [Подлинность push-доставки и права IAM](https://docs.cloud.google.com/pubsub/docs/authenticate-push-subscriptions).

Обработка нашего сервера: принять событие идемпотентно → перепроверить покупку через Developer API → обновить именно Google-источник Premium. Обычный повтор доставки не должен повторно выдавать право. Возврат Google не отзывает независимый оплаченный web-доступ; отклонение ручной заявки не отзывает Google-покупку. Сверку пропущенных возвратов разработчик реализует отдельно через Voided Purchases. [Защита покупок и отзыв прав](https://developer.android.com/google/play/billing/security).

У Pub/Sub есть тарифы/квоты: проверить Billing проекта и настроить уведомления о расходах. Подключение RTDN не требует переноса нашего приложения на Firebase, Cloud Run или другой хостинг.

## 10. Что ещё должен сделать разработчик

Настройками Console этот этап не заменить. Пока отсутствуют native Billing adapter, серверный endpoint проверки и учёт Google-покупок. Нужно реализовать:

- загрузку цены, покупку и восстановление на Android отдельно от web;
- авторизованную привязку purchase token к аккаунту SerboTalk с защитой от переноса на другой аккаунт;
- выдачу Premium только после серверной проверки PURCHASED, без выдачи в pending/cancelled;
- acknowledgement с безопасным повтором и восстановлением после сбоев;
- независимый учёт источников права, обработку RTDN и возвратов;
- RU/EN-состояния, автоматические mock-тесты и физическую приёмку.

Google возвращает средства за покупку без acknowledgement в течение трёх дней; для pending отсчёт начинается после перехода в PURCHASED. Наш бессрочный товар не потребляется. [Жизненный цикл разовой покупки](https://developer.android.com/google/play/billing/lifecycle/one-time).

Если Console просит загрузить приложение с разрешением Billing, разработчик подготовит новый AAB с интеграцией и проверит `com.android.vending.BILLING` в итоговом manifest. Новый APK/AAB не собирать из старой web-сборки. Версия Android, подпись, production API и публикация в трек проверяются отдельно по правилам проекта. До такой команды остаётся 1.40/code50; эта инструкция ничего не пересобирает.

## 11. Приёмка перед включением продаж

| Сценарий | Ожидаемый результат SerboTalk |
| --- | --- |
| Успешная тестовая покупка | Один Google-заказ, одна привязка аккаунта, Premium в Android и web |
| Отмена окна / отказ карты | Новый Premium не выдаётся |
| Pending | Доступ не выдан; появляется только после подтверждённой покупки |
| Потеря сети после оплаты | Повтор/восстановление завершает проверку без повторного списания |
| Повторная проверка token | Не создаёт второй доступ или второй аккаунт-владелец |
| Переустановка / другое устройство | Восстановление на том же аккаунте SerboTalk без второй оплаты |
| Другой аккаунт SerboTalk | Чужая покупка к нему не переносится |
| Действующий web Premium | Уже доступен в Android; повторно покупать не требуется |
| Возврат и отзыв тестовой Google-покупки | Google-право отзывается по серверному событию/сверке |
| Отдельный подтверждённый web/admin-доступ | Сохраняется при отзыве Google-источника |
| Отклонение ручной web-заявки | Не отзывает подтверждённый Google-источник |

Заказ найти в **Play Console → Order management**. Для сценария отзыва использовать доступное действие возврата **с отзывом права**, а не считать любой возврат автоматически равным revoke. После теста подтвердить, что непотребляемый товар можно снова приобрести только когда прежнее владение снято. Не включать consume в код ради повторения теста. Тестировать в RU/EN.

Перед production проверить: товар/цены/страны, merchant и выплаты, серверные secrets, проверку и acknowledgement, доставку событий, возвраты, восстановление, отсутствие внешней кассы в Android, актуальные обязательные разделы App content/Data safety и доступ ревьюеру. Фактические названия/описания платных функций должны совпадать с приложением; не обещать «безлимит», когда есть 100 повторений/сутки.

## 12. Что передать разработчику и где остановиться владельцу

Без секретов можно передать:

| Сведения | Значение / статус |
| --- | --- |
| Страна merchant profile / страна банка | Заполнить после проверки |
| Проверки профиля и банка | Завершены / ожидаются |
| Package name | Проверить `com.serbiantalk.trainer` |
| Product ID | Фактический; предлагается `premium_lifetime` |
| Purchase option ID | Фактический; предлагается `lifetime` |
| Цена EUR / страны / статус варианта | Заполнить из Console |
| Cloud Project ID / API service account email | Заполнить |
| Developer API включён / Play-права выданы | Да / нет |
| Тестовые аккаунты | Добавлены в license testers и нужный трек |
| RTDN topic / subscription / audience | Фактические значения после настройки |
| Secret backend | Только отметка «настроен», без значения ключа |

**Первая практическая точка передачи:** завершить профиль/банк, подготовить карточку товара и цены, API-account и license testers, передать несекретные идентификаторы. Затем разработчик реализует Billing, выдаёт RTDN URL и готовит согласованную тестовую сборку. После успешных тестов отдельно разрешается production-выпуск. Создание карточки товара, работа backend и публикация приложения — три разные стадии готовности.

## 13. Если что-то не работает

| Симптом | Сначала проверить |
| --- | --- |
| Нет кнопки создания товара | Merchant profile, права пользователя, подсказку Console о Billing-разрешении/сборке |
| Товар не найден приложением | Точный package/product ID, Active purchase option, регион, версию приложения и аккаунт Play; дать изменениям распространиться |
| Нет тестовой карты | License testing, сохранённый список и Google-аккаунт в диалоге покупки |
| Developer API возвращает 403 | Включён ли API, тот ли service account, выданы ли права именно в Play Console |
| Test message отправлен, backend его не видит | Subscription, правильный topic, HTTPS endpoint, OIDC/IAM, логи доставки без token/ключей |
| Premium пропал после покупки | Acknowledgement, refund/revoke, серверную привязку к аккаунту и состояние у Google |
| Console просит production access | Требования аккаунта и Dashboard; это отдельно от настройки Billing |
