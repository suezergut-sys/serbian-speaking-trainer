# Ручная оплата Premium — 26.10.2026

## Реализация

Кнопка «КУПИТЬ» открывает общую для web/Android-layout форму RU/EN. Пользователь явно выбирает страну: Россия → СБП/PayPal, Сербия → ALTA/PayPal, другая → PayPal. Смена страны отменяет неоплаченную заявку и сбрасывает метод. Для отправленной на проверку заявки изменение страны/метода заблокировано.

Стоимость — 5 EUR однократно, бессрочно; для СБП/ALTA суммы задаёт владелец. До настройки обязательных реквизитов, инструкций на обоих языках и условий активации соответствующий способ отключён. Владелец передал реквизиты: СБП 5000 RUB, ALTA 5 EUR или 550 RSD с разными счетами, PayPal 5 EUR. Значения сохранены только в ignored backend `.env`; в Git их нет. Production environment ещё не изменён. Автоматического определения страны, проверки поступлений и платёжных API нет.

Заявка создаётся при выборе доступного метода; её UUID служит уникальным номером и идентификатором для сверки. Сохраняется неизменяемая копия выданных реквизитов, инструкций и условий доступа. Пользователь копирует поля, переводит деньги и сообщает дату/время, сумму и необязательный идентификатор. Дата вводится в часовом поясе устройства, передаётся с UTC offset и сохраняется в UTC. Заявленная сумма может отличаться от ожидаемой: решение принимает администратор по фактическому поступлению.

По окончательному указанию владельца от 26.10.2026 «Я оплатил» сразу устанавливает `User.access_tier = premium` и переводит заявку в `awaiting_review`. Это предварительный бессрочный доступ, а не подтверждение получения денег. Никакого ожидания 24 часов или таймера нет. Интерфейс перечитывает аккаунт без reload и показывает: «Администратор проверит и подтвердит ваш платёж, а пока вы можете пользоваться всеми Premium-функциями без ограничений». Действуют обычные квоты Premium (100 попыток/сутки, 5 тем × 30 фраз). Повторная отправка возвращает существующие сведения и не перезаписывает отчёт. После закрытия формы/перезагрузки последняя заявка восстанавливается. Кнопка обновления получает текущий статус. Если перечитать аккаунт после отчёта не удалось, можно обновить приложение: выдача уже сохранена на сервере.

В web-админке под пользователями расположен список заявок (по 50, с навигацией и обновлением). Видны аккаунт/id, номер, страна, способ, ожидаемая и заявленная суммы, дата/ID операции, статус и проверивший администратор. Подтверждение требует отдельного подтверждения фактического поступления и сохраняет уже выданный Premium без срока. Повторное подтверждение не меняет автора/время и не выдаёт дополнительный доступ. Доступна отмена и отклонение. Они отзывают предварительный доступ только если `User.premium_payment_id` указывает на эту заявку; другой источник Premium не затрагивается. Права обычного пользователя не позволяют самостоятельно отозвать/подтвердить отправленную заявку. Конечные состояния не переводятся друг в друга.

## Настройка backend

Переменная `MANUAL_PAYMENTS` — JSON, валидируемый Pydantic. Не использовать `VITE_`: данные выдаются только авторизованным пользователям через API. По умолчанию `{}`. Ниже шаблон **без реальных реквизитов и без включённых методов**:

```json
{
  "activation": { "ru": "", "en": "" },
  "methods": {
    "sbp": { "currency": "RUB", "recipient": "", "phone": "", "bank": "", "instructions": { "ru": "", "en": "" } },
    "alta": { "currency": "EUR", "recipient": "", "account": "", "bank_details": "", "instructions": { "ru": "", "en": "" } },
    "paypal": { "amount": "5.00", "currency": "EUR", "recipient": "", "paypal": "", "instructions": { "ru": "", "en": "" } }
  }
}
```

После согласования заменить пустые строки и добавить `amount` для sbp/alta десятичной строкой с двумя знаками. `activation.ru/en` содержат согласованный текст условий немедленного доступа. `instructions.ru/en` содержат инструкции владельца. `recipient` — получатель; СБП требует `phone`, `bank`, RUB; ALTA требует `account`, `bank_details`, согласованную валюту (RSD/EUR/RUB). PayPal требует 5.00 EUR и email в `paypal` либо `paypal_url` (HTTPS на paypal.com/www.paypal.com/paypal.me/www.paypal.me). Email можно использовать без специальной ссылки: кнопка откроет PayPal, адрес доступен для копирования. Коммерческий платёж и номер заявки дополнительно объясняются общими переводами интерфейса. Назначение ALTA — `Premium <номер заявки>`. Дополнительный вариант валюты/счёта задаётся в `alta_alternative` объектом той же структуры, что `methods.alta`. В форме выбор валюты ALTA сбрасывает предыдущую неоплаченную заявку и выдаёт реквизиты соответствующего счёта. Обе суммы независимы, автоматической конвертации нет.

Неполная настройка метода оставляет его недоступным; неверные типы, неположительные суммы и небезопасный PayPal URL отклоняются при запуске. Настройки меняются в backend environment с перезапуском/redeploy. Уже выданные заявки сохраняют старые реквизиты: при их смене администратор должен учитывать старые ожидающие заявки и при необходимости отменить их.

## API, миграция и безопасность

- `GET /api/payments/options`, `GET /api/payments`, `POST /api/payments` (country/method, для ALTA дополнительно currency).
- `POST /api/payments/{id}/report` (paid_at с timezone, amount, transaction_id), `POST /api/payments/{id}/cancel`.
- Только admin: `GET /api/admin/payments?offset=0`, `PATCH /api/admin/payments/{id}` (confirmed/rejected/cancelled).
- Ответы `Cache-Control: no-store`. Чужая заявка неотличима от отсутствующей: 404. Для не-admin административные методы возвращают 403.
- Сервис, repository и модели отделены от router. Изменения сериализуются блокировкой пользователя; на SQLite используется существующая write-lock стратегия. Уникальный nullable `active_user_id` дополнительно запрещает две активные заявки на аккаунт.
- Alembic `7db9f01a2201` после `6ccb82f56983`: `payment_requests`, ограничения/индекс и nullable `users.premium_payment_id` для точного отзыва выданного доступа. Повторный upgrade head безопасен. Downgrade разрешён только для пустой таблицы; при наличии заявок требует предварительного экспорта, чтобы не потерять историю платежей.
- Тесты используют синтетические реквизиты. Никаких внешних платежей, уведомлений и AI-вызовов для новой функции.
