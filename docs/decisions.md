## 10.10.2026 — серия отказов STT и мобильные премиум-карточки

Серия неподдерживаемого алфавита считается в общем TrainerApp по завершённым пользовательским записям, а не по внутренним попыткам провайдера. После третьей записи показывается точный текст владельца с предложением перерыва. Успешный алфавит или иная ошибка STT сбрасывают серию; отменённые/устаревшие ответы не увеличивают её. Счётчик живёт в памяти текущего аккаунта, не требует API/БД и не хранит аудио. Предупреждение не отключает микрофон и не заменяет запрет оценки несербских букв.

В мобильном web и Android-layout старые раскрывающиеся действия заменены двумя карточками внутри существующей сетки тем. Добавление темы — disabled button с приглушёнными элементами, без формы; reusable PremiumBadge рисует золотую корону в золотом шестиугольнике. Это обозначение будущей платной функции, без изменения тарифов/прав backend. Добавление фразы открывает прежнюю форму. Desktop-действия остаются прежними. Shared GoldStar используется в легенде и снизу календарного дня при translation_count >=20, включая ошибочные попытки; пороги 1/10 не меняются. SettingsView использует package version без повышения, отображая v.major.minor в одной flex-строке с заголовком. Публикация и перенос в APK учитываются отдельно. [Проверки](mobile-premium-stt-checkpoint-2026-10-10.md).

## 2026-09-21 — согласованность канонического варианта и разбора

- `canonical_sr` явно передаётся в structured-анализ как обязательный корректный и естественный эталон; модель не должна предпочитать ему стилистическую альтернативу.
- `AnswerAnalyzer`, а не API/router, отвечает за согласованность результата. Если модель вернула другой `corrected_sr`, сервис сохраняет оценки и issues, но заменяет отображаемый вариант и текстовые пояснения на нейтральные формулировки, подтверждающие канон.
- UI называет поле «Канонический вариант», чтобы не смешивать постоянный учебный эталон с любым возможным естественным переводом.

## 2026-09-16 — минимальный локальный monorepo

- Backend: Python 3.12, FastAPI, Pydantic Settings, SQLAlchemy 2 и Alembic.
- Frontend: React, TypeScript и Vite; Vite dev proxy направляет `/api` в локальный backend.
- Хранилище: SQLite. Docker и внешние сервисы не добавлены.
- Границы: router вызывает сервисы, сервисы используют repositories; будущий OpenAI adapter не смешивается с Scheduler/Learner Model.
- Конфигурация: model IDs и permanent API key читаются только backend из env. Пустые model IDs допустимы, пока AI-функции не реализованы.
- Privacy by design: схема данных не содержит поля для бинарного аудио или пути к записи.
- Seed: 50 контролируемых A2 skill records и 8 preset topics; обновление выполняется идемпотентно по стабильному key/id.
- Voice gate: WebRTC не реализуется до работающего текстового вертикального цикла.
- Voice-интеграция должна повторно сверяться с официальной документацией перед изменениями: прежний Realtime client-secret flow не считается стабильным контрактом.

## 2026-09-16 — темы, сессии и генерация упражнений

- Сессия хранит snapshot нормализованной темы, поэтому изменения preset-каталога не меняют уже начатую тренировку.
- OpenAI вызывается через отдельный adapter и Responses API `parse`; результат принимается только после строгой Pydantic-валидации, запросы отправляются с `store=false`.
- Scheduler v1 детерминированно выбирает не более двух навыков с учётом темы, категории и недавних упражнений. Learner Model остаётся отдельным будущим слоем.
- Генератор делает одну повторную попытку при слишком похожей фразе. Навыки из ответа модели пересекаются с контролируемым каталогом и не могут создавать новые ключи.
- Локальный fallback позволяет пройти этапы 2–3 без API key и используется при сетевой ошибке или невалидном AI-ответе.
- Эталонные сербские варианты хранятся как внутренние подсказки генерации и не входят в публичный `ExerciseResponse`.

## 2026-09-16 — анализ текстового ответа

- `AnswerAnalyzer` использует Responses API structured output, а `AttemptService` отвечает за orchestration и сохранение; router содержит только HTTP-контракт.
- Анализ принимает несколько естественных вариантов и оценивает смысл, грамматику, лексику и естественность отдельно. Локальный fallback сравнивает со всем набором вариантов и явно остаётся деградированным режимом.
- Для text input `pronunciation_score` всегда `null`. Если переданы timing placeholders, fluency рассчитывается локально по конфигурируемым порогам и заменяет модельную оценку.
- Issues и demonstrated skills фильтруются по целевым навыкам упражнения и существующему каталогу. Модель не расширяет каталог.
- UI показывает краткий verdict сразу, а подробное объяснение, компонентные оценки и issues — в раскрываемом блоке.

## 2026-09-16 — Learner Model и адаптивный Scheduler

- `update_mastery()` — чистая ограниченная функция: correctness с confidence, fluency, naturalness и context novelty формируют performance; issue severity добавляет penalty.
- Пороговые значения состояний читаются из env. Один severe error уменьшает уже освоенный навык не более чем на 0.08, чтобы случайная ошибка не уничтожала историю.
- `LearnerModelService` атомарно с попыткой обновляет mastery, attempts, successes, hesitations, streak, `last_seen_at` и `next_review_at`.
- Интервалы повторения начинаются с 1 дня после failed, 2 дней в LEARNING, 5+ дней в CONSOLIDATING и 14+ дней в MASTERED.
- Scheduler повышает приоритет слабых, часто ошибочных и due-навыков, уменьшает частоту MASTERED и по-прежнему штрафует недавно использованные навыки.
- `AttemptResponse` возвращает только обновлённые learner snapshots; UI показывает их как компактные индикаторы прогресса.

## 2026-09-17 — пакетный голосовой ввод через Audio Transcriptions

- Live/WebRTC-вариант оказался ненадёжным для UX «наговорить одну фразу»: фрагменты транскрипта не имеют отдельного события завершения, и на реальном микрофоне текст не возвращался стабильно.
- Для короткого ответа выбран `MediaRecorder` → `multipart/form-data` → backend → OpenAI `audio/transcriptions`. Это соответствует завершённому файлу и возвращает единый итоговый transcript.
- Browser останавливает все media tracks сразу после `MediaRecorder.stop()`. Blob и backend bytes живут только в памяти, не сохраняются в файл, БД, лог или fixture.
- MIME allowlist и `MAX_AUDIO_BYTES` ограничивают вход. OpenAI-вызов использует timeout/retry из общих env-настроек; `OPENAI_TRANSCRIBE_MODEL` и permanent key читаются только backend.
- API передаёт `language=sr` и сербский prompt на дословную latinica-транскрипцию без перевода и исправления. Ответ повторно валидируется Pydantic-схемой.
- Сербская кириллица в ответе транскриптора детерминированно транслитерируется в latinica без дополнительного LLM-вызова.
- Для пакетной записи доступны duration всей записи и privacy marker. Reaction и внутренние паузы остаются `null`, пока не появится отдельная VAD/TTS временная шкала.

## 2026-09-17 — рабочее пространство практики

- Интерфейс собран в трёхколоночную композицию: каталог тем, активное упражнение и контекстная панель подсказок. На узких экранах колонки последовательно складываются, а основная навигация становится нижней.
- Подсказки и тематическая лексика берутся из существующего контракта темы; декоративные метрики и неподтверждённые учебные данные не добавляются.
- Голосовой и текстовый сценарии используют прежний API-контракт и одинаковую карточку ответа. Изменение не затрагивает хранение аудио или backend-архитектуру.
- «Статистика» и «Прогресс» доступны в навигации только как явно обозначенные заглушки до появления соответствующих read-моделей и API.

## 2026-09-17 — подсказки по словам и фразы для повторения

- Переводы слов подготавливаются вместе с упражнением как валидированный structured output и сохраняются в `target_hints_json`; browser не получает эталон всей фразы через endpoint подсказки.
- Открытие подсказки создаёт или обновляет `WordLearningItem`. `AttemptService` принимает только подсказанные слова, существующие в данных конкретного упражнения, и вычитает 0.08 за уникальное слово, но не более 0.30 за попытку.
- Попытка ниже 0.95 или использование подсказки создаёт/обновляет `ReviewPhrase`. Три самостоятельных результата от 0.95 подряд переводят её в `mastered`; любой более низкий результат сбрасывает серию.
- «Фразы для повторения» запускают отдельную сессию-карусель. Сервис случайно выбирает активную фразу, по возможности не повторяя недавние, и на каждом шаге снова читает актуальный набор, поэтому освоенная фраза больше не выдаётся.
- Пользовательская фраза сохраняется сразу. Если OpenAI настроен, отдельный structured prompt готовит допустимые переводы и пословные подсказки. В локальном fallback произвольная фраза остаётся доступной для повторения, но UI честно сообщает, что точная автоматическая проверка требует OpenAI.
- Анализ попытки перенесён в правую колонку; до ответа она содержит только нейтральное пустое состояние, без подсказок по содержанию ответа.

## 2026-09-17 — месячная статистика занятий

- Источник истины для статистики — сохранённые `Attempt`: проверка одного ответа добавляет одну фразу в статистику. День активен, если в нём есть хотя бы одна попытка.
- Месячная агрегация строится при чтении, а не хранится вторично. Выборка ограничена UTC-диапазоном и использует индекс `attempts.created_at`; даты группируются с учётом локального UTC-offset browser.
- UI даёт переключать месяцы, закрашивает активные дни зелёным и показывает под календарём дневную столбчатую диаграмму.

## 2026-09-18 — постоянный каталог фраз и расширенная статистика

- Для каждой из восьми preset-тем в `topic_phrases` хранится ровно 20 A2-фраз: утверждения и вопросы, падежные конструкции и согласование прилагательных. Seed синхронизирует их по стабильным идентификаторам и не создаёт дублей.
- У каждой записи один неизменяемый `canonical_sr`. Он используется как первый внутренний вариант проверки и как отображаемый образец независимо от формулировки AI-анализа. Альтернативный естественный ответ пользователя по-прежнему может получить высокую семантическую оценку.
- `ExerciseGenerator` сначала читает постоянный каталог и не вызывает OpenAI для preset-тем. Свои темы продолжают использовать structured AI с локальным fallback.
- Полностью выученной считается `ReviewPhrase`, которая достигла существующего правила трёх самостоятельных попыток от 95%. Момент перехода хранится в `mastered_at`; повторная активация очищает его.
- Календарный день зелёный при одной попытке и получает золотую рамку при десяти. Дневной столбик сохраняет общую высоту по всем переводам и разбивается на освоенные, остальные правильные (от 95%) и прочие попытки.

## 2026-09-19 — постоянные пословные подсказки preset-фраз

- Контекстные переводы каждого русского слова для 160 preset-фраз подготовлены через structured output с обязательной передачей `canonical_sr`, проверены на полное покрытие и совпадение грамматических форм с каноном и сохранены в версионируемом seed-каталоге. Нелитеральные эквиваленты допускаются только для явно проверенных местоимений/служебных слов, опущенных в естественном сербском варианте.
- `topic_phrases.word_hints_json` хранит подсказки вместе с каноническим переводом. `ExerciseGenerator` копирует их в snapshot упражнения, поэтому клик по слову не вызывает OpenAI и работает одинаково после перезапуска.
- Заглушка «перевод требует OpenAI» удалена. Для произвольных AI-фраз подсказки по-прежнему подготавливаются и сохраняются вместе с результатом генерации; локальный fallback выдаёт только реально известные переводы.
- Скрипт `scripts/generate_topic_phrase_hints.py` предназначен только для сопровождающего обновления каталога: использует backend timeout/retry, Pydantic-схему, проверку покрытия и локальный checkpoint. Он не запускается приложением или тестами.
- Локальный launcher перед открытием browser применяет миграции/seed и сравнивает время запуска backend со временем последней правки Python-кода. Устаревший процесс перезапускается только после проверки, что он принадлежит этому проекту; это предотвращает работу старого кода на уже занятом порту 8000.

## 2026-09-19 — детерминированная оценка точного ответа

- Нормализованное полное совпадение transcript с каноническим или другим допустимым вариантом является достаточным доказательством корректности и оценивается локально: все языковые компоненты равны 1.0, issues отсутствуют, целевые навыки получают `strong` с confidence 1.0.
- OpenAI при точном совпадении не вызывается, поэтому модель не может снизить грамматику или естественность и одновременно предложить идентичное «исправление».
- Для остальных ответов structured AI-анализ сохраняется, но backend удаляет issues с severity 0 и issues, у которых нормализованные evidence и correction совпадают.

## 2026-09-20 — интервальное повторение фраз

- `ReviewPhrase` стала состоянием карточки для каждой проверенной фразы, а не только списком ошибок. Карточка хранит тему и исходную preset-фразу через nullable foreign keys, поэтому будущие пользовательские темы смогут участвовать в той же статистике без изменения фиксированного каталога в коде.
- Трудность выводится из результата: самостоятельные 95%+ с первой попытки дают `easy`, одна ошибка перед успехом — `medium`, две и более — `hard`. Пользователь не выставляет оценку вручную; подсказка не считается успешной попыткой.
- После двух самостоятельных результатов от 95% подряд карточка становится `mastered`. Начальные интервалы равны 14, 7 и 3 дням для easy/medium/hard; следующие успешные циклы умножают предыдущий интервал на 2.5/2/1.5 с ограничением 365 дней.
- При наступлении `next_review_at` карточка атомарно возвращается в `active`, обнуляя только серию текущего цикла. История попыток, число освоений и прошлый интервал сохраняются.
- `GET /api/statistics/phrases` строит пагинированную read-модель из БД и группирует текущую страницу по `topic_presets`; интерфейс предлагает 10, 50 или все строки.

## 2026-09-20 — пустые пользовательские темы и явное распределение фраз

- `topic_presets` хранит не только готовые, но и пользовательские темы; поле `is_custom` сохраняет их происхождение. Seed добавляет «Разное» без каталожных фраз.
- Создание темы не вызывает OpenAI и не генерирует упражнения. Попытка начать пустую тему возвращает контролируемый `409`, а интерфейс предлагает сначала добавить фразу.
- Добавление пользовательской фразы разделено на два шага: `POST /api/review-phrases/prepare` получает строго валидированный канонический перевод и подсказки, затем пользователь выбирает тему и `POST /api/review-phrases` сохраняет подготовленные данные.
- Если text model не настроена или недоступна, backend не сохраняет фразу без канона и отвечает безопасной ошибкой `503`.

# 2026-09-22 — облачная граница Vercel + Supabase

- Web frontend и FastAPI backend разворачиваются как два Vercel-проекта из одного GitHub-репозитория. Это не зависит от beta-функциональности Vercel Services и даёт backend отдельные secrets и runtime-настройки.
- Supabase PostgreSQL заменяет SQLite только в cloud environment. Локальная разработка и автоматические тесты сохраняют SQLite; один набор SQLAlchemy-моделей и Alembic-миграций поддерживает оба диалекта.
- Vercel backend использует Supavisor transaction pooler, psycopg 3, `NullPool`, SSL и отключённые prepared statements. Миграции и идемпотентный seed выполняются в production build-step под PostgreSQL advisory lock, а не при импорте ASGI-приложения или его холодном старте.
- Android и browser получают только HTTPS URL backend. `OPENAI_API_KEY`, пароль PostgreSQL и любые будущие service-role credentials существуют только в environment variables backend-проекта.
- Переменный API URL остаётся доступен в настройках только администратору для диагностики. Обычные пользователи web и Android используют endpoint из сборки и не видят техническую подсказку про эмулятор. Ключ localStorage версионирован, поэтому APK облачной сборки не наследует старый LAN URL из установленного прототипа.

# 2026-09-22 — Google Auth, пользователи и дневной доступ

# 2026-09-30 — резервирование попыток и подсказки при задержках

## 05.10.2026 — причины ошибок STT и случай Allergičen

Adapter преобразует ошибки SDK в закрытые безопасные коды: timeout, connection, provider HTTP, пустой/невалидный ответ. API возвращает код в `detail` при 503; старые клиенты сохраняют общее сообщение. Web переводит коды и HTTP/network failures в русскую причину, различает клиентский timeout и отмену. Неизвестная причина обозначается явно; raw provider body, transcript и секреты в ошибку не попадают. Ошибки не меняют draft/lifecycle protections.

Первоначальная локальная политика `local-v2` добавляла формы `allergičen / alergičen → alergičan`. Она отменена следующим решением владельца в пользу анализа без словаря. Диагностика STT сохраняется. [Исторические проверки](transcription-errors-checkpoint.md).

## 07.10.2026 — общий выбор мягких подсказок

Источник настройки — `users.assistance_enabled`, boolean NOT NULL с default false. Backend предоставляет узкий авторизованный `GET/PATCH /api/auth/me/preferences` без user_id/role/access_tier в payload; запись проходит через UserService → UserRepository. `GET /api/auth/me` включает начальное значение.
