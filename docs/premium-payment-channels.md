# Premium: отдельные платежи web и Android

Решение владельца от 26.10.2026. Этот документ задаёт целевой контракт для будущих доработок; статусы реализации перечислены отдельно ниже.

## Продукт и общий доступ

Premium приобретается **однократно за 5 EUR и действует бессрочно**. Это не месячная и не годовая подписка. Для Google Play нужен невозобновляемый и непотребляемый разовый товар (one-time, non-consumable), а не subscription и не consumable. Базовая цена — 5 EUR; отображаемую локальную цену Android получает из Google Play, без копирования web-цены в native UI.

Premium принадлежит аккаунту SerboTalk. Пользователь, оплативший в web, входит в тот же аккаунт в Android и получает действующие права без повторной покупки. Покупка в Google Play также должна давать доступ этому аккаунту в web. Учетная запись Google Play сама по себе не заменяет аккаунт SerboTalk; для покупки и восстановления нужна авторизация в SerboTalk.

Существующая общая серверная проверка `User.access_tier` уже применяется обеими платформами. Бессрочный доступ не означает невозможность его отзыва при возврате/отмене платежа или отклонении предварительной ручной активации.

## Два независимых платёжных сценария

| Область | Web, включая браузер телефона | Нативное Android-приложение |
| --- | --- | --- |
| Проведение оплаты | Собственный web-сценарий; сейчас ручная оплата СБП / ALTA / PayPal | Только Google Play Billing |
| Форма и реквизиты | `PaymentForm`, существующие `/api/payments` и web-админка | Отдельный native Billing adapter и отдельный серверный API проверки покупки |
| Подтверждение | Сейчас «Я оплатил» выдаёт предварительный доступ, администратор сверяет поступление | Только проверка покупки сервером у Google; клиентский результат не выдаёт доступ |
| Цена | Текущие web-условия и настроенные реквизиты | Локализованная цена из ProductDetails Google Play |
| Общая часть | Аккаунт, право Premium, квоты и функции | Тот же аккаунт, право Premium, квоты и функции |

Нельзя объединять эти сценарии в одну форму выбора СБП/ALTA/PayPal/Google Play. Внутри Android не показывать web-реквизиты, PayPal, кнопку внешней кассы или перенаправление на web-оплату. Мобильный браузер остаётся web: ширина экрана и общий Android-layout не определяют платёжный канал. Используется `Capacitor.isNativePlatform()`.

До готовности Google Play Billing нативный экран показывает RU/EN-состояние недоступности покупки и возможность использовать уже активированный Premium через тот же аккаунт, без перехода к сторонней оплате. Такая заглушка не является интеграцией Billing.

## Следующий срез Google Play Billing

1. Подготовить платёжный профиль разработчика и разовый товар Premium в Play Console, установить базовую цену 5 EUR, выбрать страны продажи и зафиксировать реальный product ID. По сообщению владельца от 26.10.2026 профиль/товар пока не готовы; приложение проходит тестирование. Для проверки Billing использовать подходящий тестовый трек и license testers; публичный выпуск приложения не нужен для начала тестов.
2. Добавить отдельный native adapter через Capacitor с получением ProductDetails, покупкой, обработкой отмены/pending и восстановлением. Не запускать web-форму как fallback при ошибке Billing. Не потреблять бессрочную покупку через consume.
3. Добавить backend-only доступ к Google Play Developer API. Package name/product ID проверять по серверной конфигурации. Секреты сервисного аккаунта не передавать в bundle/API/Git. Привязать покупку к аккаунту SerboTalk через obfuscated account ID; не принимать произвольного владельца из клиента.
4. Проверять purchase token у Google до активации: товар, приложение, состояние PURCHASED, непотреблённость и привязку к аккаунту. PENDING не выдаёт Premium. Уникальность token и транзакции БД должны запрещать повторную выдачу/привязку другому пользователю. Token не помещать в логи, URL нашего API или диагностические ответы.
5. Реализовать acknowledgement и безопасные повторные попытки, восстановление после потери сети/перезапуска и синхронизацию уже совершённой покупки. Проверка, выдача права и acknowledgement должны выдерживать сбой между шагами и повтор запроса.
6. Хранить источник права отдельно от ручной web-заявки. Возврат покупки Google не должен отзывать независимый web/admin-доступ; отклонение web-заявки не должно отзывать подтверждённую Google-покупку. Добавить таблицы и Alembic-миграцию вместе.
7. Настроить серверные уведомления Google (RTDN) с проверкой подлинности доставки, повторной проверкой состояния через Developer API и обработкой возвратов/отзыва. Отдельно предусмотреть Voided Purchases и сверку пропущенных событий. Идемпотентная обработка, ограниченные timeout/retry, безопасные ошибки; API routers только оркестрируют сервисы.
8. Автоматические тесты — синтетические token и mock Google, без реальных оплат. Проверить дубли, чужой аккаунт, неподтверждённую/отменённую покупку, восстановление, acknowledgement failure и независимые источники Premium. Затем реальные тестовые покупки/возвраты через Play Console.

Только после этого включать покупки. Настройка env сама по себе не считается готовой интеграцией. Android sync, сборка APK и номер следующего выпуска требуют отдельной команды владельца по AGENTS.md.
