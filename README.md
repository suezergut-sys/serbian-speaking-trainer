В мобильном web и общем Android-layout карточки «+ добавить тему» и «+ добавить фразу» находятся в двухколоночной сетке тем. От 20 попыток в карточке календарного дня появляется золотая звезда; признаки от 1 и 10 попыток сохранены. Версия `v.1.27` находится справа от заголовка «Настройки». Web опубликован через PR #83; в APK изменения пока не включены, Android metadata остаются 1.27/code37. [Проверки](docs/mobile-premium-stt-checkpoint-2026-10-10.md), [production-релиз](docs/mobile-premium-web-publication-2026-10-10.md).

Локальное приложение для адаптивной тренировки быстрого перевода разговорных фраз с русского на сербский, уровень A2. Сербский текст можно показывать латиницей или кириллицей.

В «Настройках» отображается текущая версия приложения — 1.27. Web использует нумерацию Android: номер берётся из `frontend/package.json` и показывается в формате `major.minor`.

Web 1.27 опубликован, Android 1.27 (`versionCode 37`) доступен для [скачивания APK](https://github.com/suezergut-sys/serbian-speaking-trainer/releases/download/v1.27/SerboTalk-andorid16-1.27.apk). Выпуск включает текущий набор исправлений подсказок и подписей тренировки; [production/API/signature/assets проверки](docs/android-1.27-release.md). Физическая Android-приёмка остаётся открытой.

Переводы слов показываются во всплывающих подсказках с отступом от края экрана и переносом длинного текста. Счётчик текущей фразы в тренировке скрыт; снижение итоговой оценки за подсказки обозначается в процентах («Подсказки: −30%»).

Сейчас реализованы этапы 0–6: ответ произносится в микрофон и расшифровывается через OpenAI Audio Transcriptions. После распознавания пользователь может исправить текст перед проверкой; ввод ответа с клавиатуры до записи недоступен.

Android-приложение использует тот же React-интерфейс в нативном контейнере Capacitor и тот же FastAPI backend. Web и Android регистрируют пользователя и выполняют вход через Google в Supabase Auth; профиль, прогресс, темы, попытки и интервальные повторения изолированы по `user_id`.

Для облачного режима frontend и FastAPI разворачиваются как два Vercel-проекта из одного GitHub-репозитория, а `DATABASE_URL` backend указывает на Supabase PostgreSQL через transaction pooler. Web и Android используют один HTTPS API и, следовательно, одну базу фраз и повторений. Постоянный OpenAI API key хранится только в environment variables backend-проекта Vercel.

Для free-аккаунта дневной лимит составляет 10 сохранённых попыток за календарные сутки UTC; лимит применяется ко всем режимам практики, включая повторение. Администратор и аккаунт с `access_tier=premium` не ограничены; сейчас администратором назначается email из `ADMIN_EMAILS` (`suezergut@gmail.com`). Только администратор видит раздел «Пользователи» с датой регистрации, последней активностью и количеством попыток за сегодня. Платёжный провайдер пока не подключён: `access_tier` оставлен отдельным от роли, чтобы позднее webhook Lemon Squeezy или Paddle мог выдавать premium-доступ без изменения Google-входа.

Проверка ответа резервирует квоту короткой транзакцией, выполняет AI-анализ вне транзакции и сохраняет попытку атомарно после повторной проверки резервации. Повтор с тем же request ID возвращает сохранённый результат; пока анализ выполняется, API отдаёт retryable `409` с `Retry-After: 1`. Параллельные резервации учитываются в дневном лимите и длине сессии. Реализация и границы локальных проверок описаны в [контрольной точке P1.2/P1.4](docs/p1-concurrency-checkpoint.md); production проверка под нагрузкой и ручная приёмка остаются открытыми.

Интерфейс практики построен как единое рабочее пространство: темы находятся слева, а упражнение, голосовой ответ, результат и следующее действие — в одной карточке. Второстепенные формы сворачиваются. В каждой из восьми готовых учебных тем хранится по 20 разнообразных A2-фраз с постоянным разговорным сербским переводом, поэтому начало тренировки не ждёт генерации. При выборе темы фраза случайно берётся из ещё не изученных; недавние фразы не повторяются, пока есть другие. Карточка темы крупно показывает число доступных неизученных фраз: оставшиеся фразы каталога и добавленные пользователем фразы этой темы. Поэтому после добавления своих фраз счётчик может быть больше 20; такие фразы также выбираются случайно в исходной теме. Дополнительно доступна пустая тема «Разное». Пользовательские темы тоже создаются пустыми: приложение не заполняет их автоматически. «Статистика» показывает календарь активности и состав попыток за текущую неделю (понедельник–воскресенье), а ниже графиков содержит кнопку «Фразы по темам», открывающую отдельную страницу с выбором темы и состоянием интервального повторения. Выбор непустой темы сразу подготавливает первую фразу; во время ожидания видна анимация загрузки. Раздел «Прогресс» в web-навигации скрыт до реализации.

Русская фраза разбита на интерактивные слова. Контекстные переводы приходят вместе с каждой фразой и в web показываются при нажатии без ожидания нового запроса. Отдельный запрос в фоне добавляет открытое слово в список неизученных; если сохранение не удалось, интерфейс сообщает об этом. Старые Android-клиенты продолжают получать перевод через прежний endpoint. Нажатие уменьшает итог попытки на 8 процентных пунктов за уникальное слово (не более 30 пунктов). После проверки подробный разбор раскрывается внутри той же карточки.

Каждая проверенная фраза получает карточку интервального повторения. Нажатие на «Фразы для повторения» запускает карусель активных и просроченных карточек. При добавлении собственной русской фразы backend сначала создаёт и показывает канонический сербский перевод, после чего пользователь выбирает тему и только затем сохраняет фразу. Три самостоятельных результата от 95% подряд переводят карточку в «выучена» до следующей даты повторения. Трудность определяется автоматически: успех с первой попытки — лёгкая, одна ошибка перед успехом — средняя, две и более — трудная. Для новых циклов базовые интервалы составляют 3/2/1 день; после каждого следующего успешно завершённого цикла интервал умножается на 2,5/2/1,5 соответственно, но не превышает года. Уже назначенные даты повторения сохраняются.

Экран тем получает компактный счётчик повторения через `GET /api/review-phrases/summary`, сохраняя прежнюю активацию просроченных фраз. Полный список остаётся доступен старым клиентам и получает названия тем одним запросом. Проверки, локальные замеры и границы приёмки описаны в [контрольной точке P1.3](docs/p1-review-summary-checkpoint.md).

При сетевой ошибке загрузку тем можно повторить без перезагрузки. Ошибка микрофона или расшифровки оставляет возможность ввести ответ вручную; повторная запись сохраняет прежний текст до успешного STT, а поздний transcript не заменяет ручную правку. Расшифровка сообщает безопасную причину: пустой/некорректный ответ модели, неподдерживаемый алфавит, таймаут, сбой связи, ограничение запросов/квоты, отклонённая запись или HTTP-ошибка. Неизвестная ошибка явно обозначается как неизвестная; ответ провайдера и секреты не выводятся. После ошибки фоновой подготовки следующая фраза повторно запрашивается первым нажатием с прежним request ID. Проверки и ограничения: [контрольная точка P1.4](docs/p1-network-checkpoint.md).

При сворачивании или уходе из практики микрофон освобождается, текущая расшифровка отменяется, а фраза и введённый текст сохраняются. Вернувшись, можно повторить запись или продолжить вручную; поздний STT не заменит черновик. Уже отправленная оценка продолжает выполняться. Проверки и ограничения Android-переноса: [контрольная точка P1.5](docs/p1-lifecycle-checkpoint.md).

## Первый запуск

```powershell
Copy-Item .env.example .env
Copy-Item frontend\.env.example frontend\.env.local
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".\backend[dev]"
python -m app.db.cli reset --yes

Set-Location frontend
pnpm install
Set-Location ..
```

`OPENAI_API_KEY` необязателен для готовых тем и текстового локального fallback. Для создания канонического перевода новой пользовательской фразы, семантического анализа и мягких подсказок задайте `OPENAI_TEXT_MODEL`, а для голосового ввода — `OPENAI_TRANSCRIBE_MODEL`. Анализ подсказок имеет отдельный короткий бюджет `OPENAI_ASSISTANCE_TIMEOUT_SECONDS` (6 секунд по умолчанию) и `OPENAI_ASSISTANCE_MAX_RETRIES` (0 по умолчанию, максимум 1). Ключ читается только backend и `.env` исключён из Git.

Для входа настройте Google provider в Supabase Auth. В Google Auth Platform создайте OAuth client типа Web application, а callback укажите как `https://<project-ref>.supabase.co/auth/v1/callback`. В Supabase Redirect URLs разрешите `http://localhost:5173/**`, production web URL и `com.serbiantalk.trainer://auth/callback`. Публичные `SUPABASE_URL`/`SUPABASE_PUBLISHABLE_KEY` задаются backend, их Vite-версии `VITE_SUPABASE_URL`/`VITE_SUPABASE_PUBLISHABLE_KEY` — frontend. Google Client Secret и любые service-role keys в browser или APK не передаются.

Публичные страницы `/privacy` и `/terms` доступны без входа и используются в Google OAuth consent screen. Они описывают состав данных, сторонние сервисы, дневной лимит и правило хранения обычного аудио только во временной памяти и временное исключение для собственного аудио разрешённого debug-admin.

При production-deploy backend один build-step применяет миграции и идемпотентный seed. PostgreSQL advisory lock не даёт двум production-сборкам изменять схему одновременно. Preview не меняет production-базу. Ту же операцию можно безопасно повторить вручную:

```powershell
$env:DATABASE_URL = "postgresql://..."
python -m app.db.cli seed
```

Vercel-функция не запускает миграции при холодном старте. Backend переиспользует до одного постоянного соединения с Supabase transaction pooler на тёплый экземпляр функции (и до двух дополнительных при одновременных запросах), проверяет соединение перед использованием и отключает prepared statements. DB credentials остаются только в backend; browser и APK их не получают.

Для диагностики задержек web-интерфейс можно открыть с параметром `?perf=1`: консоль покажет отдельно время получения сессии, сетевого запроса и серверные `Server-Timing`. Параметр не влияет на обычный режим.

При открытии приложения список тем становится доступен сразу после ответа `/api/topics`; фразы для повторения загружаются затем в фоне. Повторные события Supabase Auth с тем же токеном не вызывают новый запрос профиля.
В Android статистика запрашивается только при открытии её панели, а нажатие темы переключает панель без длительной анимации. После оценки ответа клиент в фоне подготавливает следующую фразу; обновление профиля и списка повторения не блокирует кнопку «Следующая» и начинается после подготовки фразы. Если фоновая подготовка завершилась ошибкой, первое нажатие «Следующая» повторяет запрос с прежним ID.
Backend проверяет Google ES256 access tokens локально по JWKS Supabase с кешем на пять минут; для остальных токенов остаётся проверка через Supabase Auth. Локальная проверка учитывает отзыв токена не раньше его срока истечения. Запросы навыков и их состояний объединены, чтобы сократить число обращений к удалённой БД.

## Реализованный текстовый сценарий

- `GET /api/topics` — список восьми готовых тем, пустой темы «Разное» и пользовательских тем.
- `POST /api/topics` — создание сохранённой пустой пользовательской темы.
- `POST /api/topics/normalize` — нормализация своей темы.
- `POST /api/sessions` — новая сессия со snapshot темы.
- `POST /api/sessions/start` — новая сессия и первая фраза вместе с пословными переводами в одном запросе; web-интерфейс использует этот путь для обычной тренировки и карусели повторения. Канонический ответ в payload упражнения не передаётся.
- `GET /api/sessions/{id}` — состояние сессии.
- `POST /api/sessions/{id}/next-exercise` — следующее упражнение из постоянного каталога preset-темы; для своей темы используется прежний AI/fallback-поток.
- При выборе упражнения состояния навыков текущего пользователя загружаются пакетно; генератор повторно использует загруженный каталог навыков вместо отдельного запроса на каждый навык.
- `POST /api/attempts` — анализ текстового ответа, сохранение попытки и ошибок.
- `POST /api/transcriptions` — расшифровка короткой записи из памяти без передачи API key во frontend.
- `POST /api/review-phrases/prepare` — подготовка валидированного канонического перевода пользовательской фразы.
- `GET/POST /api/review-phrases` — список фраз для повторения и сохранение подготовленной фразы в выбранную тему.
- `POST /api/exercises/{id}/word-hints` — добавление открытого слова в неизученные и получение перевода для старых клиентов; web отправляет запрос в фоне после показа перевода.
- `GET /api/learning-words` — текущий список слов, открытых через подсказки.
- `GET /api/statistics/monthly?month=YYYY-MM&utc_offset_minutes=...` — общее число переводов, правильные результаты от 95% и полностью освоенные фразы по дням месяца в локальном часовом поясе пользователя.
- `GET /api/statistics/phrases?page=1&page_size=10|50|all` — фразы, сгруппированные по темам из БД, с числом попыток, статусом и датой следующего повторения.

Если ответ после нормализации полностью совпадает с каноническим или другим допустимым вариантом, backend детерминированно выставляет 100% без вызова OpenAI. Нормализация учитывает сербскую кириллицу и Unicode NFC, сохраняя различия между `c`, `č` и `ć` и реальные лишние буквы. В остальных случаях настроенный OpenAI использует Responses API со strict Pydantic structured outputs и `store=false`. Замечание должно ссылаться на слова распознанного ответа и содержать реальное отличие, а не различие только в алфавите или Unicode. Самопротиворечивый анализ повторяется не более одного раза; при повторной ошибке, недоступности AI или некорректном ответе попытка не оценивается, прогресс и дневной лимит не меняются. Неизвестные `skill_key` не принимаются. Для близкой замены одного слова пояснение строится из проверенной пары исходного слова и исправления, чтобы модель не приписывала ошибку другой букве. Карточка результата всегда показывает сохранённый канонический вариант; если модель предложила вместо него стилистическую альтернативу, backend согласованно заменяет и вариант, и пояснение, чтобы подробный разбор не ставил канон под сомнение.

Обычная сессия завершается после проверки заданного числа различных упражнений; web обычно запрашивает 10. Это ограничение длины одной сессии независимо от дневного лимита. Дневной лимит free-аккаунта — 10 сохранённых попыток за UTC сутки, независимо от режима; admin и premium не ограничены. Повтор с тем же `client_request_id` возвращает прежнюю попытку и не создаёт дополнительную запись.

Сохранение попытки и выдача следующей фразы поддерживают необязательный `client_request_id`: повтор с тем же ID возвращает прежний результат и не создаёт вторую попытку или упражнение. Старые клиенты могут не передавать ID и сохраняют прежний API-контракт. В web результат и действия по нему находятся вместе с карточкой практики; фраза и форма ответа сохраняются на экране, второстепенные действия можно свернуть.

После каждой попытки Learner Model обновляет mastery целевых навыков, состояния `LEARNING`/`CONSOLIDATING`/`MASTERED`, streak и дату следующего повторения. Отдельный планировщик карточек фраз ведёт трудность, серию успешных ответов, растущий интервал и автоматически возвращает просроченные карточки в очередь. Темы карточек ссылаются на таблицу `topic_presets`, поэтому статистика не зависит от фиксированного списка тем. UI показывает обновлённый прогресс навыков в обратной связи.

## Голосовой ввод

В карточке упражнения нажмите «Ответить голосом» и разрешите браузеру доступ к микрофону. Browser записывает короткую фразу через `MediaRecorder` в память. После нажатия «Завершить запись» все media tracks останавливаются, Blob отправляется как `multipart/form-data` на backend и передаётся в OpenAI Audio Transcriptions с языком `sr`. Поле редактирования появляется только после успешной расшифровки.

В разделе «Настройки» выберите латиницу или кириллицу для сербских переводов слов, ответов, канонических вариантов и статистики. Выбор сохраняется на устройстве отдельно для каждого аккаунта. Данные и оценка остаются в латинице; отображение преобразуется локально, поэтому отдельные столбцы и миграция БД не нужны. Расшифровка отображается в текущем выбранном алфавите, в том числе после его смены во время запроса. Составные Unicode-символы приводятся к NFC перед отображением и отправкой. При ручном редактировании похожие русские буквы внутри преимущественно латинских слов приводятся к латинице, например `kartiсom` → `karticom`; сербская кириллица и различия `c`/`č`/`ć` сохраняются.

Допустимы только поддерживаемые audio MIME-типы, размер ограничен `MAX_AUDIO_BYTES` (по умолчанию 1 МБ), а внешний запрос использует общий timeout и ограниченный retry. Вне разрешённой отладки backend не пишет аудио в файл, БД или лог; после STT временные байты освобождаются до дополнительного текстового анализа. Если модель вернула сербскую кириллицу, результат детерминированно приводится к latinica и NFC; буквы других письменностей отклоняются безопасной ошибкой. Это не заменяет проверку смысла: STT может ошибиться в распознавании слова, и текст перед оценкой можно отредактировать. При успешном анализе подсказок в БД сохраняется текстовый receipt с проверенными предложениями; после проверки ответа сохраняется текст попытки. Бинарное аудио допускается только временным исключением debug-admin от 12.10.2026.

При таймауте/невалидном анализе/отсутствии настройки показывается исходная расшифровка и сообщение о недоступности помощи; тренировку можно продолжить.
